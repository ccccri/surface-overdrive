# Workarounds for other projects' bugs

Patches and settings that exist only because of a bug in Fedora, KDE or another project, not because of the Surface. Each
one goes once the project fixes it. Where the build can tell by itself, the patch steps aside (the package is then Fedora's
as it is) and the build log says so; the rest need a look at each Fedora release.

| What we do | Whose bug | Where | Fixed when | Remove |
|---|---|---|---|---|
| Brightness & Color popup scrolls only up and down (`contentWidth: availableWidth`) | KDE powerdevil: the brightness applet's scroll view is wider than the popup, a finger drags it sideways (6.8.2, master on 2026-11-07) | `ci/patch_powerdevil.py`, `ci/build_powerdevil.sh`, stage `powerdevil` in the Containerfile, `tests/test_powerdevil_patch.py` | the build log says "already sets contentWidth (fixed by Plasma, Fedora's package is fine)" | the four files and the stage |
| No "Update Issue" for Discover's own repeated firmware metadata download | KDE Discover: it checks for updates twice at start and refreshes LVFS twice; fwupd refuses the second download within 1.5 s (`FWUPD_ERROR_NOT_REACHABLE`, "attempted previous download ... just 847ms ago") and Discover shows it as an error (6.8.2 with fwupd 2.1.9) | `ci/patch_discover.py`, `ci/build_discover.sh`, stage `discover` in the Containerfile, `tests/test_discover_patch.py` | the build log says "already knows fwupd's repeated download (fixed by Discover...)"; or Discover stops refreshing twice (the error no longer shows with Fedora's package) | the four files and the stage |
| Kernel dumps from EFI to the journal (`Storage=journal`) | Fedora selinux-policy: systemd-pstore may not create its per-boot directories in `/var/lib/systemd/pstore` (`avc: denied { create } ... tclass=dir`), so dumps stayed in the firmware's variables | `image/rootfs/usr/lib/systemd/pstore.conf.d/50-surface-overdrive.conf` | no such AVC denial in the journal with the file moved aside, and `/var/lib/systemd/pstore/<boot>/` directories appear | the file (or keep it: the journal is a fine place for them) |
| Apps of the image from Flathub when Fedora's OCI remote cannot be used by a system service | flatpak with Fedora's OCI registry: its authenticator needs a session bus ("Cannot autolaunch D-Bus without X11 $DISPLAY") | `preinstall_without_oci()` in `src/overdrive/flatpaks.py` | `flatpak preinstall --system` of an app only Fedora has works from `systemd-run --wait` | the function and its call |
| Fedora's OCI remote not listed in Discover (`--no-enumerate`) | Kinoite's defaults: Fedora's remote next to unfiltered Flathub, twice (system and user), most apps listed twice | `unlist_oci_remotes()` in `src/overdrive/flatpaks.py` | a fresh Kinoite with one remote, or Discover merging the two | the function and its calls (the setting it made stays) |
| libcamera's IPA modules signed at the right path | Fedora's libcamera spec re-signs `%{_libdir}/libcamera/ipa_*.so` after the modules moved to `ipa/`: unsigned modules run isolated and the camera stalled | `ci/build_libcamera.sh` (the signing line) | Fedora's spec signs `ipa/ipa_*.so` | the replacement in the script |

Not workarounds, for the record: the lock screen, login screen, PAM, plasma-pa, dim screen and Plasma default patches
(`ci/patch_lockscreen.py`, `patch_unlock_pad.py`, `patch_pam.py`, `patch_plasma_pa.py`, `patch_dimscreen.py`,
`patch_plasma_defaults.py`) and the libcamera series are features or tuning of this project, kept on purpose.
| systemd-remount-fs skipped on ostree systems | Fedora 45's installer: `/` is "ro" in /etc/fstab, and systemd-remount-fs cannot remount the composefs root ("overlay: No changes allowed in reconfigure"), a failed unit at every boot | `image/rootfs/usr/lib/systemd/system/systemd-remount-fs.service.d/50-surface-overdrive.conf` | a fresh install without the drop-in shows no failed systemd-remount-fs | the drop-in |
| grub-boot-success only with a writable /boot | Fedora 45: the user unit writes GRUB's environment block in /boot, which a fresh install mounts read-only ("Creating tmpfile failed: Read-only file system") | `image/rootfs/usr/lib/systemd/user/grub-boot-success.service.d/50-surface-overdrive.conf` | Fedora gives it a way to write (or drops it) | the drop-in |
